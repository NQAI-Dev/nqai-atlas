# NQAI Atlas — недельная линия развития

## Принцип
Atlas — каноническая память решений и состояния NQAI. OpenClaw остаётся исполнителем и интерфейсом. Atlas не становится вторым агентом, планировщиком или каналом связи.

## Этапы

### Неделя 1 — надёжное ядро
- [x] append-only JSONL
- [x] `add`, `search`, `explain`, `verify`
- [x] MCP stdio: поиск, добавление, объяснение, проверка
- [x] тесты CLI и MCP на чистом временном хранилище
- [x] строгая проверка схемы и безопасная запись при параллельном доступе

### Неделя 2 — модель мира
- [x] сущности: project, service, host, decision, person
- [x] явные связи `relates_to`, `depends_on`, `runs_on`
- [x] команда `context <entity>`: текущее состояние + решения + связи
- [ ] импорт существующих долговечных записей из Markdown только вручную

### Неделя 3 — операционная память
- [x] снимки состояния Git-проектов как observations
- [x] health-check записи с источником и timestamp
- [ ] история изменений без потери старых утверждений
- [ ] MCP-ресурс для контекста конкретной сущности

### Неделя 4 — автономные циклы
- [ ] Atlas предлагает следующий шаг, но не выполняет рискованные действия сам
- [ ] еженедельный обзор устаревших решений и незакрытых целей
- [ ] отчёт о прогрессе с доказательствами: коммит, тест, URL или blocker
- [ ] только после стабильности — поиск по смыслу; не тащить vector DB заранее

## Критерий успеха
Через месяц запрос по любой важной сущности должен вернуть: текущее состояние, почему оно такое, источник, связанные сущности и устаревшие решения. Каждый ответ должен быть проверяемым локально.
